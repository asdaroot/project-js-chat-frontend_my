# Chat Frontend

Фронтенд учебного чат-мессенджера на React + TypeScript + Vite. Работает в паре с бэкендом `@hexlet/chat-server` (Fastify + Socket.IO + JWT), который предоставляет REST API и realtime-сокеты.

## Возможности

- Вход в систему по логину и паролю (`POST /api/v1/login`)
- Регистрация нового пользователя по логину и паролю (`POST /api/v1/signup`) — вкладка «Регистрация» на экране входа
- Окно чата после входа: сайдбар с каналами, сообщения выбранного канала
- Выбор канала кликом — показываются только его сообщения
- Отправка сообщений через Socket.IO в реальном времени
- Управление каналами в модальных окнах: создание, переименование, удаление (с подтверждением)
- Обновление каналов и сообщений в реальном времени: изменения других клиентов применяются сразу
- Выход из системы и возврат к форме входа
- Сессия (JWT-токен + имя) сохраняется в `localStorage`: перезагрузка страницы не требует повторного входа

## Установка

```bash
npm install
```

## Запуск

Бэкенд должен быть доступен по адресу из конфигурации (см. ниже), по умолчанию `http://192.168.233.128:3000`.

```bash
npm run dev -- --host --port 8000
```

Фронтенд будет доступен по адресу `http://localhost:8000/` (и по сетевому адресу машины, напр. `http://192.168.233.128:8000/`).

> Порт 8000 выбран потому, что порт 3000 уже занят бэкендом. Если нужно переопределить — замените `--port` на нужное значение.

## Конфигурация

URL бэкенда задаётся в переменной окружения `VITE_API_URL`. Значение по умолчанию — `http://192.168.233.128:3000`.

Скопируйте пример конфигурации при необходимости:

```bash
cp .env.example .env.local
```

`VITE_API_URL=http://192.168.233.128:3000`

## Тесты

Проект покрыт юнит- и компонентными тестами: **Vitest + jsdom + Testing Library** (73 теста). Тесты лежат рядом с кодом (`*.test.ts` / `*.test.tsx`) и не требуют запущенного бэкенда — внешние зависимости замоканы: `fetch` замокан на уровне `lib/api`, Socket.IO — на уровне `lib/socket` (`src/test/socketMock.ts`).

Запуск:

```bash
npm test                # однократный прогон всех тестов
npm run test:watch      # режим watch при разработке
npm run test:coverage   # прогон с отчётом покрытия
npx tsc --noEmit -p tsconfig.vitest.json   # проверка типов тестовых файлов
```

Что покрыто:

- **`lib/session`** — сохранение/восстановление/очистка сессии в `localStorage`, обработка битых данных
- **`lib/api`** — `login`/`signup`/`fetchData`: успех, ошибки (401, 409, сеть), заголовок `Authorization`
- **`App`** — вход, регистрация, клиентская валидация, восстановление сессии, выход
- **`ChatWindow`** — загрузка и повтор при ошибке, выбор канала, отправка сообщений, realtime-события, управление каналами (создание/переименование/удаление), выбор канала при удалении
- **Компоненты** — `ChannelSidebar`, `MessageList`, `MessageForm`, `ChannelDialog`, `Modal`

Отдельные тесты фиксируют текущее поведение сверх спеки как есть (без изменения кода): авто-скролл к последнему сообщению, отсутствие дедупликации сообщений по id, отсутствие отдельного пустого состояния при удалении последнего канала.

Ничего дополнительно устанавливать не нужно: тестовые зависимости уже входят в `devDependencies` и подтягиваются обычным `npm install`.

## Структура

```
src/
  App.tsx               — экран входа, регистрация, сессия в localStorage
  App.css               — стили интерфейса (включая окно чата и модалки)
  index.css             — глобальные стили и переменные
  types.ts              — типы данных (Channel, Message, ChatData)
  lib/api.ts            — обёртки над REST API (login, signup, fetchData, BASE_URL)
  lib/socket.ts         — клиент Socket.IO
  lib/session.ts        — хранение сессии в localStorage
  components/
    ChatWindow.tsx      — окно чата: состояние каналов/сообщений, подписка на сокет
    ChannelSidebar.tsx  — список каналов и выбор
    MessageList.tsx     — сообщения выбранного канала
    MessageForm.tsx     — форма отправки сообщения
    ChannelDialog.tsx   — модалка создания/переименования/удаления канала
    Modal.tsx           — коробка модального окна
```

## API бэкенда

- `POST /api/v1/login` — вход: `{ username, password }` → `{ token, username }`
- `POST /api/v1/signup` — регистрация нового пользователя
- `GET /api/v1/data` — начальное состояние чата (каналы и сообщения), требует `Authorization: Bearer <token>`
- Socket.IO (без авторизации): отправка `newMessage`, `newChannel`, `removeChannel`, `renameChannel`; приём одноимённых broadcast-событий

Тестовый пользователь по умолчанию — `admin` / `admin`.

Документация по Socket.IO-событиям и бэкенду: репозиторий `@hexlet/chat-server`.

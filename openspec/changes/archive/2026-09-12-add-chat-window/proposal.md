## Why

Авторизованный вид сейчас — это заглушка: список названий каналов и счётчик сообщений из одной загрузки `GET /api/v1/data`. Пользователь после логина должен попадать в настоящий чат: выбирать каналы, читать их сообщения, отправлять свои, управлять каналами в реальном времени. Бэкенд `@hexlet/chat-server` это целиком поддерживает через Socket.IO (`newMessage`, `newChannel`, `removeChannel`, `renameChannel`); REST для записи такого не имеет. Заодно сессия (токен) становится персистентной через `localStorage`.

## What Changes

- Авторизованный вид `AuthenticatedView` заменяется на полноценное окно чата: сайдбар с каналами слева, сообщения выбранного канала справа, поле ввода внизу.
- Выбор канала: клик по каналу показывает его сообщения; канал по умолчанию — `currentChannelId` из `GET /api/v1/data`.
- Отправка сообщений: `socket.emit('newMessage', { body, channelId, username })`; входящие `newMessage` докладываются в список в реальном времени.
- Управление каналами через модальные окна: создание («Добавить канал», `newChannel`), переименование (`renameChannel`), удаление с подтверждением (`removeChannel`). При удалении текущего канала выбор переключается на первый оставшийся; сообщения удалённого канала пропадают.
- Подписка на broadcast-события `newMessage`, `newChannel`, `removeChannel`, `renameChannel`, чтобы состояние не расходилось с другими клиентами.
- Новая зависимость: `socket.io-client` (совместим с серверным socket.io 4.8.3).
- Сессия сохраняется в `localStorage` (`{ token, username }`): при загрузке страницы авторизованное состояние восстанавливается, после logout чистится. **BREAKING** для сценария «reload возвращает на форму входа» — теперь reload сохраняет вход.
- Блок с токеном в авторизованном виде удаляется (это был отладочный вывод). **BREAKING**

## Capabilities

### New Capabilities

- `chat`: Окно чата, в котором авторизованный пользователь выбирает канал и видит его сообщения, отправляет сообщения в реальном времени и управляет каналами (создание, переименование, удаление) через модальные окна, а также получает чужие изменения каналов и сообщений через Socket.IO.

### Modified Capabilities

- `user-auth`: Требование «Authenticated user sees initial chat state» переносится в capability `chat` (окно чата вместо summary-вида). Требование «Authenticated user sees their session token» удаляется. Требование «User can log out» меняется: сессия сохраняется в `localStorage`, повторная загрузка страницы сохраняет вход, logout очищает хранилище.

## Impact

- Зависимости: добавление `socket.io-client`.
- Файлы: `src/App.tsx` (bootstrap сессии из localStorage, окно чата вместо summary), новые компоненты в `src/components/` (окно чата, сайдбар, список сообщений, форма сообщения, модалка), `src/lib/socket.ts` (клиент сокета), `src/lib/api.ts` (не меняется), `src/types.ts` (по необходимости).
- Стили: `src/App.css` (раскладка чата, модалки) — шаблонные стили summary удаляются.
- Бэкенд не меняется; REST-контракт остаётся прежним.
